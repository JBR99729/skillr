# Old quiz route retirement — 2 November 2026

Owner request: replace the separate website quiz and test players with practice in app.skillrhub.com. This supersedes the earlier requirement to keep the legacy player journey running. Topic teaching content, slide viewers, worksheets/homework, source question files and learner browser storage are retained. No app bank, account access, marking or saved attempt is changed.

`scripts/retire_legacy_quiz_routes.py --write` migrates the tracked public HTML routes and navigation. It uses the existing production-verified `data/app-question-banks.json` (222 published banks, verified 2 November). A published code uses `?try=1&skill=CODE` only where the verified guest flag allows it; other matching codes use `?login=1&skill=CODE`. Tests, reviews, results and retakes also lead to practice, as requested. A code without a published matching bank, and mixed drills, lead to the app catalogue. No unrelated skill is silently substituted and no DEV bank is advertised. App authentication and explicit learner selection remain intact.

GitHub Pages does not support per-route server redirect configuration. Every existing legacy HTML URL is therefore retained as an immediate HTML meta refresh with a native link and `location.replace` fallback. All target URLs are fixed to the app domain; incoming score, query, fragment and identity parameters are discarded. The stubs contain no legacy question scripts, have `noindex,follow`, and are removed from XML sitemaps and website search results. Paper worksheets and homework under `/quiz/` remain available. Existing app assessment links remain assessments; only old website test links become app practice.

The migration rewrites native player links on published pages without touching their teaching text, comments, inline scripts, styles or non-player resource links. Historical research, tests, exports and backup directories are excluded. Source bank JavaScript is retained for recovery but no longer loaded by old player routes. The current service worker already fetches navigation HTML without caching, so it loads the redirect stubs on subsequent visits.
