# Years 7–10 topic-module upgrade progress

This manifest tracks completion against the new connected topic-module standard: an in-depth topic page, a four-core-slide teacher deck, and one dedicated nine-question practice source with a 3/4/2 difficulty split, answer, one-sentence summary and actionable hint for every question. The nine questions are presented exactly once across two stable printable routes: Topic Practice 1 contains questions 1–5 and Topic Practice 2 contains questions 6–9, with a subset-only answer key on each sheet.

## Preservation and repurposing strategy

- Preserve every useful existing topic explanation, elaboration, model, visual, teacher note, worked example, misconception, checkpoint, extension and curriculum reference.
- Repurpose canonical accessible models and alt descriptions into the topic deep-dive and the concept-refresher slide.
- Expand useful worked models and checkpoints into two detailed topic-page worked examples and the guided-instruction and Quick Check slides.
- Consolidate useful slides beyond the four required core roles into teacher notes, optional extensions, topic-page explanation or practice-sheet reasoning prompts.
- Retain exact curriculum wording in a clearly separated reference layer; do not use raw syllabus wording as the student-facing explanation.
- Preserve routes, navigation, Quick Read/read-aloud, Practice/Test links, certificates, student-name settings, downloads, reporting, access controls, PWA behaviour and SkillrHub branding.
- Keep existing worksheet routes and download controls while replacing the old reused-question payload with a dedicated nine-question 3/4/2 source. Publish it as Topic Practice 1 and Topic Practice 2 with a stable 5/4 split, no question deletion or duplication, and a sheet-specific answer key containing the answer, summary and hint for every displayed question.
- Keep public logo and product branding in renderer chrome rather than instructional content. Store curriculum identity, guides, slide content and both worksheet partitions in a deterministic brand-neutral export so a later isolated private pipeline can create editable commercial masters without changing the public pages.
- Keep useful legacy PDFs available where appropriate while making the live four-core-slide deck the primary teaching link.
- Do not modify assessment question banks, Daily Drills, Foundation resources, SEO, sitemaps or unrelated workbook/certificate files.

## Special handling: AC9S8U01

AC9S8U01 is a valid Year 8 Science code but currently has a deliberately separate canonical asset and renderer path from the other upper-years Science modules. It must be included explicitly in registry, generation and validation totals. Its detailed cell models, microscopy material, two worked examples, misconceptions and accessible descriptions are useful source content and must be migrated or adapted without loss. No generator may silently omit it because it is absent from `year8-science-full-data.js`.

## Completion rule

A batch changes to **Complete** only after every listed code has all three deliverables, deterministic validation passes, representative and high-risk visual review passes, the PR is mergeable with no failed checks, and the batch is squash-merged. The PR URL, merge commit and exact validation result must then be recorded in this file.
