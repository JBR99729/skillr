Learn the skill

Small steps, clear examples

Learning goal: An algorithm is a clear set of instructions. Follow steps in order, make decisions, stop at the stated point and use results to investigate number patterns.

Before you start: Add, subtract, double and recognise simple multiples and odd/even numbers.

Useful words: algorithm: ordered instructions; condition: a yes/no test; repeat: do a step again; trace: record each value; debug: find and repair an instruction error.

1. Follow steps in order

Keep a record of the current value after every instruction. A later step acts on the value you have now.

7 + 3 = 1010 × 2 = 2020 − 4 = 16

Worked example: start at 7 → add 3 → double → subtract 4. The trace is 7 → 10 → 20 → 16.

Reversing the middle steps changes the result: double 7, then add 3, then subtract 4 gives 13. An ordered algorithm is more precise than a loose list of operations.

Watch for this: Use the current value, not the original start, at each step.

Try it: Start at 6, double, add 5, then subtract 3. Record every value.

Check the answer and explanation

6 → 12 → 17 → 14.

2. Repeat with a stopping rule

A repeating instruction needs a clear stopping condition. Decide when the test occurs and whether to record the starting value.

Worked example: record 3. Check the current number: if it is less than 15, add 4, record the new number and check again; otherwise stop. The list is 3, 7, 11, 15. At 15 the condition “less than 15” is false.

Investigate doubling: record 3, then double and record four times: 3, 6, 12, 24, 48. Each new value has two equal copies of the previous one. Read backwards and halve: 48, 24, 12, 6, 3. State the finite repeat count before starting.

Watch for this: “Less than” excludes equality. Check where the stop test belongs.

Try it: Record 2. While the current number is less than 14, add 3 and record it. What is the full list?

Check the answer and explanation

2, 5, 8, 11, 14. Stop at 14 because it is no longer less than 14.

3. Choose the correct decision branch

A decision asks a question with a yes or no answer. Follow exactly one branch, then continue as instructed.

Worked example: if the input is greater than 10, subtract 3; otherwise add 4; record the answer and stop. Input 14 follows yes and gives 11. Input 6 follows no and gives 10. Input 10 follows no and gives 14.

Classify numbers: for each of 8, 15 and 20, ask separately “Is it a multiple of 2?”, “of 5?” and “of 10?”. Record every yes, then stop after all three tests. Results: 8→2; 15→5; 20→2, 5 and 10. A number may belong in more than one group, so do not stop at its first yes.

Watch for this: Test equality and both branches; do not treat “greater than 10” as “10 or more”.

Try it: Use the rule “if the number is even, halve it; otherwise add 1; then stop”. Test 12 and 7.

Check the answer and explanation

12 is even, so the output is 6. 7 is odd, so the output is 8. Do not apply the first branch again unless instructed to repeat.

4. Create instructions someone else can follow

Give a start, ordered actions, any decision and a clear finish. Test your instructions with a different person or a written trace.

Worked example: to generate five multiples of 4: “Start at 0. Add 4 and record the result. Repeat the add-and-record step until five results are recorded. Stop.” The outputs are 4, 8, 12, 16, 20.

A diagram with start/action/decision/stop can show the same procedure. A digital tool can run the steps after the instructions are checked.

Watch for this: “Make a pattern of fives” is less precise than executable steps and a stopping rule.

Try it: Write an algorithm that records four multiples of 5, starting with 5.

Check the answer and explanation

One valid answer: start at 0; add 5 and record; repeat until four results are recorded; stop. Outputs 5, 10, 15, 20.

5. Find the first error, repair and retest

Compare the intended instructions with a trace. Locate the first disagreement, then check the repair with contrasting inputs.

Worked example: rule: add 2, then double. A trace for input 5 says 5 → 7 → 12. The first action is correct, but doubling 7 should give 14. Repair that step. Retest input 0: 0 → 2 → 4.

If an algorithm follows the wrong branch, repair the condition or arrow before testing both possible paths again.

Watch for this: A corrected final answer alone does not explain which step failed.

Try it: A rule says subtract 1, then multiply by 3. A trace reads 8 → 7 → 24. Repair it and test input 4.

Check the answer and explanation

The final value should be 21. For input 4: 4 → 3 → 9.

6. Investigate and describe an emerging pattern

Keep a table of inputs and outputs. State what the results suggest and explain how the rule produces it.

Worked example: for “double, then add 1”, inputs 0, 1, 2, 3 produce 1, 3, 5, 7. Every output in the table is odd. Doubling makes an even number; adding one gives the next odd number.

Build a multiplication algorithm: save the original input, double it, then add the saved original and stop. For input 4: save 4; double to 8; add the saved 4 to get 12. Three copies of the input explain why this is multiplying by 3. Test 2→6 and 5→15.

Use a small spreadsheet to generate further inputs if available, checking its first results by hand. Several trials can support an observation; a reason tied to the instructions is stronger than a guess.

Watch for this: Distinguish a pattern noticed in examples from a reason that explains the rule.

Try it: Investigate “double, then add 2” for inputs 1, 2, 3 and 4. Describe and explain the outputs.

Check the answer and explanation

4, 6, 8, 10. Doubling a whole number makes an even number; adding two keeps it even.

Common mistakes and quick fixes
  • Use the current value, not the original start, at each step.
  • “Less than” excludes equality. Check where the stop test belongs.
  • Test equality and both branches; do not treat “greater than 10” as “10 or more”.
  • “Make a pattern of fives” is less precise than executable steps and a stopping rule.
  • A corrected final answer alone does not explain which step failed.
  • Distinguish a pattern noticed in examples from a reason that explains the rule.
Check understanding and choose the next step
  1. Start at 4, add 6, then halve.
  2. If an input is at least 8, subtract 2; otherwise add 2. Find the output for 8.
  3. Write a stop rule that gives exactly three recorded outputs.
Answers and next step
  1. 4 → 10 → 5.
  2. 6; “at least” includes 8.
  3. For example, count recorded outputs and stop when the count reaches three. Include the start and action instructions in the full algorithm.

If an answer is uncertain, reopen the matching focus, use its model and explain a fresh example before the test.

Support: Use movable instruction cards and a separate current-number card. Trace one action at a time before adding a branch.

Extend within this topic: Create an algorithm with a decision and a finite stopping condition. Test a below-boundary, equal-boundary and above-boundary input.

An adult can read the directions aloud. Let the learner show reasoning with objects, a drawing, pointing or a spoken explanation where appropriate. For an actual measuring, creating or data-collection task, the learner still performs and records the stated skill; provide suitable supervision.
