Algorithms for Sorting & Classifying Shapes

Turn geometric definitions into precise flow charts, decision trees and hierarchies for triangles, quadrilaterals and polygons.

LearnHomeworkPracticeTest

What this topic is really about

An algorithm is a finite, ordered and reproducible set of instructions. In this topic, geometric properties become decision rules. Instead of saying “this looks like a square”, a reliable algorithm asks precise questions such as “Are all four sides equal?” and “Are all four angles 90°?”.

A strong classification algorithm has clear inputs, exact conditions, complete branches and a final output. Different correct algorithms may test properties in different orders, provided they classify every valid input consistently.

1. Triangle classification algorithms

A useful triangle algorithm can classify by sides and angles.

By sides: all three equal → equilateral; exactly two equal → isosceles; all different → scalene.

By angles: one 90° → right; one greater than 90° → obtuse; otherwise all are less than 90° → acute.

Why order matters: if you ask “Are two sides equal?” before checking “Are all three equal?”, an equilateral triangle could be prematurely labelled isosceles. Test the more specific condition first or explicitly allow hierarchical classifications.

2. Quadrilateral algorithms and hierarchies

Quadrilaterals overlap in their properties, so a hierarchy is often more useful than a flat list.

  • Exactly one pair of parallel sides: trapezium, using the convention for this unit.
  • Two pairs of parallel sides: parallelogram.
  • Parallelogram + four right angles → rectangle.
  • Parallelogram + four equal sides → rhombus.
  • Both rectangle and rhombus conditions → square.
  • Two pairs of adjacent equal sides can identify a kite in this classification scheme.

A square should not be treated as unrelated to rectangles and rhombuses: it satisfies both definitions. If a final single label is required, return the most specific supported class.

3. Polygon classification algorithms

For a general polygon, three useful decisions are:

  1. Count sides to identify the polygon family: triangle, quadrilateral, pentagon, hexagon, heptagon, octagon and so on.
  2. Check regularity: all sides equal and all interior angles equal → regular; otherwise irregular.
  3. Check concavity: any interior angle greater than 180° → concave; otherwise a simple polygon with all interior angles less than 180° is convex.

Example: a five-sided polygon with unequal sides and one reflex interior angle is an irregular concave pentagon.

4. Flow charts and decision trees

ElementPurpose
Start/endmarks entry or final output
Process/actionperforms a step such as “count sides”
Decisionasks a condition such as “all sides equal?”
Branchfollows YES/NO or another defined outcome

Every relevant decision needs complete branches. A decision tree with a YES path but no NO path can leave some valid shapes unclassified.

5. Testing and debugging an algorithm

Good algorithms should be tested with contrasting examples and boundary cases. Useful test shapes include an equilateral triangle, an isosceles triangle, a square, a non-square rhombus, a non-square rectangle, a trapezium, a convex pentagon and a concave pentagon.

Counterexample debugging: the rule “four equal sides → square” is wrong. A non-square rhombus is a counterexample. The corrected rule is “four equal sides AND four right angles → square”.

Likewise, “four right angles → square” is too strong; a non-square rectangle disproves it.

6. Choosing an efficient decision order

There can be more than one correct algorithm. For example, a polygon algorithm might check side count first, then regularity, then concavity. Another could check concavity first and still be correct if every branch remains complete and the same final classifications are reached.

Order becomes critical when a branch stops too early. If an algorithm outputs “rectangle” and stops before checking equal sides, it misses the more specific classification “square”.

Common mistakes

  • Using appearance-based questions such as “Does it look like a diamond?”.
  • Forgetting the isosceles branch between equilateral and scalene.
  • Treating four equal sides as sufficient for a square.
  • Treating four right angles as sufficient for a square.
  • Using only side equality to decide whether a polygon is regular.
  • Confusing concavity with irregularity.
  • Stopping at a broad class when a more specific class should still be checked.
  • Leaving a decision branch incomplete.

Answer guide

Precise deterministic rules; three equal sides; check whether exactly two sides are equal; use 90° and >90° angle tests; count parallel-side pairs; rectangle = four right angles, rhombus = four equal sides within the parallelogram family; square satisfies both; regular = equal sides and equal angles; concave = at least one reflex interior angle; a rhombus can have equal sides but unequal angles; a non-square rhombus is a counterexample; incomplete branches leave valid inputs without outputs; test diverse and boundary examples; different orders can work if all paths remain logically complete and produce the same classifications.
